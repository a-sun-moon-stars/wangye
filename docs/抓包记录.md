# 抓包记录 · 一次页面请求里发生了什么

> 对应任务书里的「顺手完成的抓包练习」：按 F12 进 Network，记录 3 条请求——页面主文档、一个 CSS 或 JS、一次自己写的 `fetch`；再故意请求一个不存在的路径，截图看看 404 长什么样。
>
> 这份文件既是操作说明，也是实测记录。下面「我的实测记录」已填入 2026-11-11 本地 Python 服务的真实数字；部署到 GitHub Pages 后，建议用线上地址重测并替换耗时。

---

## 一、先准备环境

推荐用本地 HTTP 服务打开，而不是双击 HTML：

```bash
cd wangye
python -m http.server 8000
```

浏览器访问 `http://localhost:8000`。

原因：双击时是 `file://` 协议，`fetch('data/tasks.json')` 会被浏览器拦截，Network 里就不会出现第 3 条请求。页面有兜底数据，仍然能看，但抓包练习会少一条。

## 二、F12 操作步骤

1. 用 Chrome / Edge 打开页面。
2. 按 `F12`（或右键 → 检查），切到 **Network** 面板。
3. 勾选 **Preserve log**（保留日志），勾选 **Disable cache**（禁用缓存）。
4. 按 `Ctrl + R` 刷新页面。
5. 在请求列表里找到这三条：

| # | 请求 | 怎么找 | 预期类型 | 预期方法 | 预期状态 |
| --- | --- | --- | --- | --- | --- |
| 1 | `index.html` | 列表最上面的 Document | `document` | `GET` | `200` |
| 2 | `css/style.css` 或 `js/app.js` | 筛 `CSS` 或 `JS` | `stylesheet` / `script` | `GET` | `200` |
| 3 | `data/tasks.json` | 筛 `Fetch/XHR` | `fetch` | `GET` | `200` |

6. 依次点开每条请求：
   - **Headers → General**：看 `Request Method`、`Status Code`；
   - **Timing**：看 `Waiting for server response`（TTFB）或底部总耗时；
   - **Response**：确认返回的是 HTML / CSS / JSON，而不是错误页。
7. 在地址栏手动访问一个不存在的路径，例如：

```text
http://localhost:8000/data/not-found.json
```

8. 回到 Network，找到这条 `not-found.json`，确认状态码是 **404**。截图保存为 `screenshots/network-404.png`：当前仓库附的是地址栏直接访问时的 404 响应页；如果老师要求 F12 面板里请求名和状态码同框，再截一张 Network 面板图替换。

> 注意：这个 404 是**故意制造**的练习，不算“控制台有红色报错”。拍完 404 截图后，刷新首页，确认正常页面的 Console 是干净的；作业提交时说明“404 为抓包练习”。

## 三、每条记录要写什么

| 字段 | 从哪里看 | 说明 |
| --- | --- | --- |
| 请求名称 | Name 列 | 例如 `index.html`、`style.css`、`tasks.json` |
| 请求类型 | Type 列 | `document` / `stylesheet` / `script` / `fetch` |
| 方法 | Headers → Request Method | 本页全部是 `GET` |
| 状态码 | Headers → Status Code | 正常是 `200`；练习 404 是 `404` |
| 耗时 | Timing → 总时长 / Waiting | 单位 ms，写你机器上的实测值 |
| 大小 | Size 列 | 传输大小，可选填 |
| 发起者 | Initiator 列 | 谁触发了请求，例如 `app.js` / `store.js` |

### 三条请求分别说明了什么

1. **`index.html`（Document）**  
   浏览器先向服务器要 HTML。服务器返回 200 和 HTML 文本，浏览器开始解析。它是整棵 DOM 树的起点。

2. **`css/style.css`（Stylesheet）或 `js/app.js`（Script）**  
   HTML 里的 `<link>` / `<script>` 触发第二次请求。CSS 会阻塞渲染，JS 用 `defer` 延后到 DOM 解析完再执行。200 表示服务器找到了文件，类型也正确。

3. **`data/tasks.json`（Fetch）**  
   页面里的 `fetch('data/tasks.json')` 发出的请求。它由 JavaScript 主动发起，不是地址栏导航；返回 JSON 后，代码把任务渲染成列表。这条最能说明“请求是怎么发出去的”。

### 404 说明了什么

`404 Not Found` 不是服务器坏了，而是“服务器收到了请求，但对应路径没有资源”。它和 `500`（服务器内部错误）不是一回事。看到 404 时先检查路径拼写、文件是否真的存在、部署后大小写是否一致（GitHub Pages 区分大小写）。

## 五、写进周记的三句话（可直接改用）

1. 打开页面时，浏览器先请求 `index.html`，再根据 HTML 里的 `<link>` 和 `<script>` 去请求 CSS 和 JS；我写的 `fetch('data/tasks.json')` 是页面加载后由 JavaScript 主动发出的那条。
2. 这些请求都是 `GET`，正常返回 `200`；我故意访问 `data/not-found.json` 时返回 `404`，说明服务器收到了请求，但路径下没有这个资源。
3. 耗时看 Timing 里的 Waiting（TTFB）和总时长；本地服务通常只有几毫秒，线上会受网络影响，所以记录要写自己机器上的真实值。

## 六、常见问题

**Q：为什么刷新后看不到 `tasks.json`？**  
A：可能用了 `file://` 打开，fetch 被拦截；或者 Network 没勾 Preserve log，刷新后旧记录被清掉。用本地 HTTP 服务并重新刷新。

**Q：状态码是 304 而不是 200？**  
A：浏览器用了缓存。勾选 **Disable cache** 再刷新，或者按 `Ctrl + Shift + R` 强制刷新。

**Q：`tasks.json` 的 Initiator 显示 `store.js`，不是 `app.js`？**  
A：正常。`fetch` 封装在 `js/store.js` 的 `loadTasks()` 里，`app.js` 调用它。看 Initiator 的调用栈就能看到两层。

**Q：404 那一请求在 Console 里有红字，算不算“控制台不能有红色报错”？**  
A：这是练习故意制造的 404，提交时单独说明即可。正常首页的 Console 应当是干净的；如果首页本身有红色报错，那才是需要修的问题。

**Q：线上 GitHub Pages 的耗时为什么比本地大？**  
A：请求要经过网络和 CDN。记录线上地址时写线上的实测值，不要拿本地毫秒数冒充线上。
